# Sabaq AI

Сайт для учителей Казахстана: по теме урока за пару минут получить презентацию (PPTX) и игру для класса на казахском или русском.

## Как работаем
- Код пишет в основном Claude, Марлен изучает каждый шаг и делает небольшие задачи сам. Объясняй решения простыми словами, новые понятия — коротко при первом появлении.
- Сначала фронтенд на моковых данных, бэкенд (Gemini, PostgreSQL) — потом.
- Работаем в ветках `feat/...`, в `main` напрямую не коммитим.

## Архитектура
- Главный контракт — пакет темы: `src/types/topic-package.ts` (схемы zod → типы TS, JSON Schema для Gemini и проверка данных). Слайды и игры собираются из него по шаблонам без AI. При несовместимых изменениях схемы повышай `schemaVersion` и обновляй моки (новые необязательные поля, как `templateId`, версию не меняют); лимиты списков — в `limits`, их же используют конструкторы.
- AI: `src/lib/ai/` — `gemini.ts` (единственное место с запросом к Gemini, модель из `GEMINI_MODEL`, по умолчанию `gemini-3.5-flash-lite`), `prompts.ts` (короткие промпты), `generate.ts`. Без `GEMINI_API_KEY` — демо-режим из `src/lib/demo.ts`; демо-урок из кэша при появлении ключа создаётся заново. Gemini отвечает 400 INVALID_ARGUMENT на «тяжёлые» схемы, поэтому `toGeminiSchema` убирает `maxItems` (количество задаёт промпт, лимиты проверяет zod). Ключ — только в `.env.local`, не в `.env.example` (он в git).
- База — Supabase (Postgres) через REST без библиотек: `lib/db.ts` (`select/insert/update/upsert/remove/count`, секретный ключ только на сервере, RLS включён без правил). Схема — `supabase/schema.sql` (запустить в SQL Editor). Ключи `SUPABASE_URL`, `SUPABASE_SECRET_KEY` — в `.env.local` и в Vercel.
- Хранилище: `lib/storage/` — `lessons.ts` (урок целиком в `data` jsonb + колонки для списков; id случайный, у каждого учителя свои уроки; общий кэш AI `ai_cache` по `cacheKey` = хэш «тема+класс+язык(+предмет, кроме физики)(+вид, кроме урока)»; повторный запрос той же темы открывает свой урок), `rooms.ts` (rooms/players/answers, уникальный ключ (ученик, вопрос) не даёт ответить дважды), `activity.ts`, `usage.ts` (журнал запросов к AI, дневной лимит `DEFAULT_DAILY_LIMIT`, у админов без лимита; оборачивай вызовы AI в `tracked`).
- Вход: свой, без писем (`lib/auth.ts`): логин (email или слово) + пароль scrypt, cookie `sabaq-session` на год (в базе хэш токена). Роли admin/teacher, статусы pending/active/blocked; первый зарегистрированный — админ; с кодом приглашения учитель сразу активен. Для мамы — одноразовая ссылка `/login/link/[токен]` из админки. Страницы — `requireUser()/requireAdmin()` внутри Suspense, API — `currentUser()` → `apiError("unauthorized")`; `src/proxy.ts` только переадресует без cookie на `/login`. Открыто без входа: `/login`, `/play`, ученические API комнат. Свой урок — `canWrite`, чужой из библиотеки (`featured`) — только просмотр и «Көшіріп алу» (`/api/lessons/[id]/copy`).
- Админка `/admin` (вкладки: учителя и коды приглашения, расход AI по дням и учителям, ошибки AI, статистика, библиотека): `lib/admin.ts` + `components/admin/`, API `/api/admin/*` через `adminOrError()`.
- Құралдар `/tools` (`components/tools/Tools.tsx`, данные `data/physics.ts`): опыты PhET в iframe (`?locale=kk|ru`), справочник формул 7–11 классов с поиском, постоянные, перевод единиц, конвертер — ссылки на convertio.co.
- Картинки на слайды «текст+рисунок» и «большой рисунок» при создании урока ищутся сами (`lib/slide-images.ts`, Wikimedia по `imageQuery` примеров; поиск — `lib/images.ts`), хранятся ссылкой в `pkg.deck[id].image`; в PPTX — `addImage` с подписью автора, без картинки — заглушка PowerPoint.
- Режим на главной «AI жазады / Бос жоба» (`mode` в запросе): пустой проект — заготовка с подсказками из `emptyContent` (`lib/demo.ts`), `source: "empty"`, случайный id без кэша.
- Кнопка «AI» у каждого слайда, вопроса теста, утверждения и вопроса «Өз ойын»: `POST /api/lessons/[id]/generate` (`types/ai.ts`, `generatePart` + `partPrompt`) пишет одну часть, сервер её не сохраняет — страница вставляет её как обычную правку, поэтому работает «Болдырмау» (`components/lesson/AiButton.tsx`, `AiProvider`; без ключа кнопок нет). Для слайда что брать/куда класть — `slideAiPart` в `SlideFields.tsx`.
- API: `POST /api/lessons` (создать или взять из кэша), `GET/PUT /api/lessons/[id]` (автосохранение конструктора), `POST /api/lessons/[id]/jeopardy` («Өз ойын» генерируется отдельно, по запросу).
- Игры: шаблоны в `src/games/registry.tsx`. Шаблон = способ показать часть пакета (`quiz`, `trueFalse`, `jeopardy`), а не новые данные: Тест и Викторина делят одни вопросы. Новая игра = запись в реестре + плеер + (если нужно) редактор в `src/components/games/`.
- Презентация: `src/slides/`. `templates.ts` — шаблоны (цвета, шрифты Arial/Calibri/Georgia, украшение); новый шаблон = новый объект. `layout.ts` — `buildSlides` превращает пакет в слайды из элементов (rect/circle/text) в % и пунктах. Их рисуют два «художника»: `components/slides/SlideCanvas.tsx` (превью) и `export-pptx.ts` (PPTX через pptxgenjs, в браузере). Меняй раскладку только в `layout.ts`, тогда превью и файл не разойдутся. Два разных выбора: **стиль** (`templates.ts`, `templateId` — цвета/шрифты, в интерфейсе «Стиль») и **вид презентации** (`deckType`: урок, открытый урок/конкурс, отчёт, доклад, классный час, родительское собрание, аттестация). Вид = список слайдов в `slides/structures.ts`: раскладка (`layoutSchemas` в topic-package) + тексты-подсказки kk/ru + иконки. Правки учителя — `pkg.deck[id слайда]`, проверяются схемой раскладки при чтении (`slideData`); у вида «урок» id прежние (goals, textImage…). Новый вид = значение в `deckTypeSchema` + список в `structures` + `deckTypes` в словарях + строка в `deckTypePrompt`. Вид входит в хэш id урока (кроме «урока»).
- Конструктор презентации — по слайдам: `components/slides/SlideEditor.tsx` (миниатюры с заголовками + выбранный слайд) и `SlideFields.tsx` (поля по раскладке). При создании с AI тексты всех заготовок пишутся параллельно с пакетом темы (`generateDeck`, одна схема на все слайды); то же — кнопка «Барлық слайдты AI-мен толтыру» (`FillDeckButton`, part `deck`). AI не выдумывает личные данные для отчётов/портфолио — ставит «…».
- Главная — мастер из 3 шагов (`TopicForm.tsx`): тема+язык → предмет+класс → результат (презентация/игра, вид презентации, AI/пустой проект).
- Кнопки списков в конструкторах (удалить, ↑ ↓ вместо перетаскивания) — `components/ui/ItemButtons.tsx`, помощники `moveItem`/`replaceAt` — `ui/field.ts`. «Өз ойын» на табло — темы строками, как в «Своей игре»; учитель может довести тем до 6 (`limits.jeopardy`), AI даёт 3–5.
- Иконки: `src/slides/icons.ts` (Lucide, ISC). В превью SVG, в PPTX — PNG (в браузере через canvas, в скрипте через resvg), чтобы открывалось и в старом PowerPoint.
- Место под картинку (`type: "image"`) в PPTX — настоящая заглушка PowerPoint «нажмите, чтобы вставить рисунок» через макет слайда. pptxgenjs 4.0.1 теряет у неё `type="pic"`, поэтому `pptxBytes` дописывает его в XML. Скругление `rectRadius` в pptxgenjs — доля от короткой стороны (не от половины).
- `npm run sample:pptx` — пробные PPTX во всех шаблонах в `data/samples/`, их можно открыть в PowerPoint.
- Игра через QR (переключатель «Экранда / QR арқылы», флаг `qr` в реестре игр; Өз ойын — только экран): учитель создаёт комнату (`POST /api/rooms`, код из 6 цифр, копия вопросов), ученики заходят на `/play/[код]` и отвечают в своём темпе; правильность проверяет сервер, ответы на телефон заранее не уходят. Экран учителя `components/games/RoomHost.tsx` опрашивает `/api/rooms/[код]` каждые 2 с. Экран учителя и управление игрой — только её учителю.
- Перемешивание в QR-игре (галочка при запуске, `room.shuffle`): при входе ученику записываются `order`/`optionOrders`, `/play` отдаёт вопросы в его порядке, а `resolveAnswer` (`lib/rooms.ts`) переводит номер вопроса и кнопки обратно в исходные — ответы и статистика хранятся по исходным номерам.
- «Жарыс» (`race`, как Kahoot, `live: true` в реестре — только через QR): `room.live` — фаза lobby/question/reveal/finished; учитель ведёт её `POST /api/rooms/[код]/live` (start/reveal/next), экран учителя `RaceRoom` в `RoomHost.tsx` сам показывает ответ, когда вышло время или ответили все. Ответ принимается только на текущий вопрос и пока идёт время (`RACE_SECONDS` + 2 с), очки и время считает сервер. Оба экрана опрашивают сервер раз в секунду. Плитки ▲◆●■ — `components/games/race.ts`.
- Анализ по вопросам: `questionStats` → `QuestionStats` (в `ResultsTable.tsx`) на экране учителя и в истории игры: % верных, красным — меньше половины, самый частый неверный ответ.
- Пока сайт не опубликован, телефоны заходят по адресу ноутбука в Wi-Fi (`/api/network`); для этого в `next.config.ts` есть `allowedDevOrigins` для 192.168.*.* и т.п.
- Картинки в вопросах (тест/викторина и «Өз ойын»): храним только ссылку `{ url, credit }` (`imageSchema`, только https), файлы не храним. Выбор — `components/games/ImagePicker.tsx`: поиск в Wikimedia Commons через `/api/images` (без ключа, с User-Agent) или вставка ссылки. Показ — `components/ui/RemoteImage.tsx` (`<img referrerPolicy="no-referrer">`). В схемах для AI (`quizQuestionSchema`, `jeopardySchema`) картинок нет, чтобы модель не выдумывала ссылки; хранимые версии — `quizItemSchema`, `jeopardyStoredSchema`.
- История (`/history`, ссылка «Тарих» в панели): `lib/history.ts` собирает её из уроков (createdAt), комнат QR-игр (с результатами, страница `/history/game/[код]`) и журнала activity (`lib/storage/activity.ts`) — туда пишутся скачанный PPTX и игра на экране (при первом ответе) через `lib/track.ts` → `POST /api/activity`.
- Даты: `lib/dates.ts`, пояс `Etc/GMT-5` (весь Казахстан с 2024 — UTC+5; «Asia/Almaty» в старой базе поясов Node 20.11 ещё UTC+6 и ломает гидратацию). Формат собираем сами (30.10.2026 17:08), не через локаль kk-KZ — в Node её нет. «Сегодня/вчера» считаем на сервере.
- Страница урока: `/lesson/[id]?tab=slides|games` — только то, что выбрано на главной (вторая часть — тихой ссылкой), и «Конструктор / Алдын ала көру». `?view=1` — только просмотр (из истории), `&game=` — какую игру открыть.
- Состояние страниц сохраняется при переходах (cacheComponents держит их в `<Activity>`): флаги «загрузка» не делаем через useState перед `router.push`, а используем `useTransition`, иначе при возврате кнопка «крутится» вечно.
- Ключи API только на сервере в `.env.local` (шаблон — `.env.example`), никогда в клиентском коде и не в чате.

## Дизайн интерфейса
- Стиль macOS/iOS: фон `bg-bg`, карточки `bg-surface` с `rounded-2xl`, полупрозрачная панель `bg-glass backdrop-blur-xl`, акцент системный синий `accent`.
- Цвета только через токены из `src/app/globals.css` (`text-label`, `text-label-2`, `bg-fill`, `border-separator` …), без жёстких hex в компонентах — так работает тёмная тема.
- Базовые компоненты в `src/components/ui/` (Button, Card/ListGroup, SegmentedControl, NavBar). Сначала переиспользуй их.
- Размеры текста только через шкалу iOS (`text-body`, `text-subhead`, `text-footnote`, `text-title1` …) в rem, без `text-[17px]`: переключатель «А А А» меняет размер шрифта у `<html>`, и всё должно масштабироваться.
- Тема и размер текста: `src/lib/preferences.ts` (хуки) и `preferences-script.ts` (скрипт в `<head>`, без хуков — его импортирует серверный layout).
- Главный пользователь — учителя 55–60 лет: крупные кнопки (от 44px), понятные подписи вместо одних иконок, подтверждение перед удалением, автосохранение.
- Стиль интерфейса ≠ 10 шаблонов презентаций: шаблоны — отдельный конфиг (этап 3+).

## Язык
- Интерфейс на казахском и русском: переключатель ҚАЗ/РУС в панели, выбор в cookie `sabaq-lang`. Словари `src/i18n/kk.ts` (эталон) и `ru.ts` — новый текст добавляй в оба, иначе tsc ругается. В клиентских компонентах `useT()` из `@/i18n/client`, в серверных и API `await getT()` из `@/i18n/server` (читает cookie — только внутри Suspense; layout уже обёрнут). Ошибки API — `apiError("ключ", статус)`: текст на языке сайта + `code` для кода.
- Язык сайта ≠ язык урока: слайды, вопросы, «Шын/Жалған» — на языке урока.
- Проверяй, что казахские буквы (ә ғ қ ң ө ұ ү һ і) отображаются.
