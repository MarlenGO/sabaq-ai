# Sabaq AI

Сайт для учителей Казахстана: по теме урока за пару минут получить презентацию (PPTX) и игру для класса на казахском или русском.

## Как работаем
- Код пишет в основном Claude, Марлен изучает каждый шаг и делает небольшие задачи сам. Объясняй решения простыми словами, новые понятия — коротко при первом появлении.
- Сначала фронтенд на моковых данных, бэкенд (Gemini, PostgreSQL) — потом.
- Работаем в ветках `feat/...`, в `main` напрямую не коммитим.

## Архитектура
- Главный контракт — пакет темы: `src/types/topic-package.ts` (схемы zod → типы TS, JSON Schema для Gemini и проверка данных). Слайды и игры собираются из него по шаблонам без AI. При несовместимых изменениях схемы повышай `schemaVersion` и обновляй моки (новые необязательные поля, как `templateId`, версию не меняют); лимиты списков — в `limits`, их же используют конструкторы.
- AI: `src/lib/ai/` — `gemini.ts` (единственное место с запросом к Gemini, модель из `GEMINI_MODEL`, по умолчанию `gemini-3.5-flash-lite`), `prompts.ts` (короткие промпты), `generate.ts`. Без `GEMINI_API_KEY` — демо-режим из `src/lib/demo.ts`.
- Хранилище: `src/lib/storage/lessons.ts`, JSON-файлы в `data/lessons/` (в .gitignore). id = хэш «тема+класс+язык» — это и кэш тем. Перед деплоем на Vercel заменить на PostgreSQL (только этот файл).
- API: `POST /api/lessons` (создать или взять из кэша), `GET/PUT /api/lessons/[id]` (автосохранение конструктора), `POST /api/lessons/[id]/jeopardy` («Өз ойын» генерируется отдельно, по запросу).
- Игры: шаблоны в `src/games/registry.tsx`. Шаблон = способ показать часть пакета (`quiz`, `trueFalse`, `jeopardy`), а не новые данные: Тест и Викторина делят одни вопросы. Новая игра = запись в реестре + плеер + (если нужно) редактор в `src/components/games/`.
- Презентация: `src/slides/`. `templates.ts` — шаблоны (цвета, шрифты Arial/Calibri/Georgia, украшение); новый шаблон = новый объект. `layout.ts` — `buildSlides` превращает пакет в слайды из элементов (rect/circle/text) в % и пунктах. Их рисуют два «художника»: `components/slides/SlideCanvas.tsx` (превью) и `export-pptx.ts` (PPTX через pptxgenjs, в браузере). Меняй раскладку только в `layout.ts`, тогда превью и файл не разойдутся. В колоде 15 слайдов: 5 с содержанием пакета и 10 заготовок с текстом-подсказкой (цели, план, текст+картинка, большая картинка, сравнение, цифры, обсуждение, задание с дескрипторами, рефлексия, домашка).
- Иконки: `src/slides/icons.ts` (Lucide, ISC). В превью SVG, в PPTX — PNG (в браузере через canvas, в скрипте через resvg), чтобы открывалось и в старом PowerPoint.
- Место под картинку (`type: "image"`) в PPTX — настоящая заглушка PowerPoint «нажмите, чтобы вставить рисунок» через макет слайда. pptxgenjs 4.0.1 теряет у неё `type="pic"`, поэтому `pptxBytes` дописывает его в XML. Скругление `rectRadius` в pptxgenjs — доля от короткой стороны (не от половины).
- `npm run sample:pptx` — пробные PPTX во всех шаблонах в `data/samples/`, их можно открыть в PowerPoint.
- Игра через QR (переключатель «Экранда / QR арқылы», флаг `qr` в реестре игр; Өз ойын — только экран): учитель создаёт комнату (`POST /api/rooms`, код из 6 цифр, копия вопросов), ученики заходят на `/play/[код]` и отвечают в своём темпе; правильность проверяет сервер, ответы на телефон заранее не уходят. Экран учителя `components/games/RoomHost.tsx` опрашивает `/api/rooms/[код]` каждые 2 с. Хранилище `lib/storage/rooms.ts`: файл на каждого ученика, чтобы одновременные ответы не затирали друг друга.
- Пока сайт не опубликован, телефоны заходят по адресу ноутбука в Wi-Fi (`/api/network`); для этого в `next.config.ts` есть `allowedDevOrigins` для 192.168.*.* и т.п.
- Картинки в вопросах (тест/викторина и «Өз ойын»): храним только ссылку `{ url, credit }` (`imageSchema`, только https), файлы не храним. Выбор — `components/games/ImagePicker.tsx`: поиск в Wikimedia Commons через `/api/images` (без ключа, с User-Agent) или вставка ссылки. Показ — `components/ui/RemoteImage.tsx` (`<img referrerPolicy="no-referrer">`). В схемах для AI (`quizQuestionSchema`, `jeopardySchema`) картинок нет, чтобы модель не выдумывала ссылки; хранимые версии — `quizItemSchema`, `jeopardyStoredSchema`.
- Страница урока: `/lesson/[id]` — вкладки «Презентация / Ойындар» и «Конструктор / Алдын ала көру».
- Ключи API только на сервере в `.env.local` (шаблон — `.env.example`), никогда в клиентском коде и не в чате.

## Дизайн интерфейса
- Стиль macOS/iOS: фон `bg-bg`, карточки `bg-surface` с `rounded-2xl`, полупрозрачная панель `bg-glass backdrop-blur-xl`, акцент системный синий `accent`.
- Цвета только через токены из `src/app/globals.css` (`text-label`, `text-label-2`, `bg-fill`, `border-separator` …), без жёстких hex в компонентах — так работает тёмная тема.
- Базовые компоненты в `src/components/ui/` (Button, Card/ListGroup, SegmentedControl, NavBar). Сначала переиспользуй их.
- Размеры текста только через шкалу iOS (`text-body`, `text-subhead`, `text-footnote`, `text-title1` …) в rem, без `text-[17px]`: переключатель «А А А» меняет размер шрифта у `<html>`, и всё должно масштабироваться.
- Тема и размер текста: `src/lib/preferences.ts` (хуки) и `preferences-script.ts` (скрипт в `<head>`, без хуков — его импортирует серверный layout).
- Главный пользователь — учителя 55–60 лет: крупные кнопки (от 44px), понятные подписи вместо одних иконок, подтверждение перед удалением, автосохранение.
- Стиль интерфейса ≠ 10 шаблонов презентаций: шаблоны — отдельный конфиг (этап 3+).

## Язык
- Тексты интерфейса на казахском (`lang="kk"`), русский добавим позже через переводы. Проверяй, что казахские буквы (ә ғ қ ң ө ұ ү һ і) отображаются.
